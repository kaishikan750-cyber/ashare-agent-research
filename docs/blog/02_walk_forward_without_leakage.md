# 我怎样让量化 Agent 的 walk-forward 可以被检查

单次全样本回测容易成为“参数调到最好看”的故事。我在第三阶段加入滚动 walk-forward，目的首先是可验证的时间协议：每一个参数决定都能找到当时输入，而不是从好看的收益曲线猜原因。

## 训练和测试在代码里隔开

默认固定 60 个观测交易日训练，留 2 日间隔，再测 20 日；窗口逐次滚动。训练参数是 0.1、0.2、0.5 分位，含佣金/税/滑点的训练净收益最大者胜出，平局取较小分位。收益只是一个简单明确的工程选参准则；小样本下它很容易过拟合，不代表最佳金融研究实践。

`cn_research/study.py` 在训练前实际裁掉未来行情：

```python
prefix = df[df.date <= window["train_end"]]
train = run_backtest(
    prefix,
    start=window["train_start"],
    quantile=q,
    costs=costs,
    eligible_codes=eligible,
)
```

过去日期可暖启动前收盘；训练起点之前的信号和持仓不会继承。训练末持仓仅盯市当时价格，不用测试区间的退出价格判断候选收益。两日间隔覆盖名义持有跨度；遇到受阻退出也不会为了补齐未来交易而读取后续数据。

结果 JSON 每折保存训练日期、排除日期、测试日期、全部 training_candidates 和 selected_quantile。后续训练可以使用已经发生的早期测试日期，这是滚动更新的正常含义；它仍不等于最终独立 holdout。

## 最容易被忽略的是跨窗账本

如果每折测试都重新初始化现金、强制清仓，然后把收益相加，会抹去尚未退出的持仓和真实现金占用。我的实现先生成测试日期到分位的 schedule，再对全部测试窗跑一次连续引擎。参数只决定新信号；旧仓仍按原到期规则卖出，卖不出就延期。

逐折收益使用前一折末净值作为起点，因此：

```text
整体收益 = ∏(1 + 每折收益) - 1
```

测试检查它与完整样本外账本一致。最后少于四天的尾段被排除；报告明确最终评估日期，不能把缺失尾段藏起来。

## 敏感性与股票池不拿来重选赢家

第三阶段在同一测试期提供分位 × 单边滑点网格，并比较全池、沪主板、深主板。敏感性是事后描述。如果查看网格后按赢家重新生成样本外结果，就又使用了测试数据。多个股票池挑赢家同样有选择偏差。测试改变敏感性滑点集合，walk-forward 选参和样本外主账本必须保持不变。

默认股票池是文件内静态代码，不是官方历史指数成分。我增加了自定义静态代码和历史 memberships。每条历史记录需要 known_at、生效起点和可选结束点，日期资格只在当时信号日检查。来源与当时是否已知仍需要研究者核实，程序不能认证一个 CSV 的历史真实性。

## 基准为何不直接写“跑赢沪深 300”

我没有可靠官方指数数据，因而实现的是同池等现金买入持有和现金零利息。等权持有在样本外首日开盘一次买入，用相同佣金、滑点和整手规则；期末盯市，不卖出，所以不收卖出印花税。策略有换手，基准无换手；它们日期相同、资金相同，但暴露和交易次数不同。收益差不应被命名为显著 alpha。

## 用什么证据证明没有未来函数

`tests/test_stage3.py` 包含两个重要反例测试：修改第一测试窗以后的价格，不改变第一折训练候选与选参；修改更晚的价格，不改变更早样本外净值。还检查跨参数窗卖出受阻持仓继续存在、T+1、现金非负、基准手续费和整手、历史成分时间线、窗口不足显式失败。测试有实际金融语义，不只是检查函数名是否存在。

人工样例的三个池均为负收益，报告保留这些结果。演示数据无真实 A 股统计含义。工程链路验证之后，还要做更长真实样本、历史股票池、公司行动、交易日历和最终独立 holdout 检验。
